# RegionWatch — full stack (users, single admin, server-held DeepSeek key)

## Что здесь

- `backend/` — сервер (Node.js + Express + Postgres). Отдаёт и API, и сам сайт (`frontend/`) — один процесс, один деплой.
- `frontend/` — тот же сайт с картой, теперь ходит на `/api/...` вместо локальной памяти браузера.

Карта регионов, как и раньше, использует ваш собственный `russia.geojson` — положите его в `frontend/` рядом с `index.html` (скачать: `https://raw.githubusercontent.com/codeforamerica/click_that_hood/master/public/data/russia.geojson`).

## Как это устроено (коротко)

- Кто угодно может зарегистрироваться — но регистрация всегда создаёт обычного пользователя (`role='user'`). Роль `admin` через форму получить нельзя.
- Единственный админ создаётся один раз скриптом `create-admin.js` из `ADMIN_EMAIL`/`ADMIN_PASSWORD` в `.env`.
- Обычный пользователь, войдя, может отправлять обращения.
- Только админ видит и может менять поле DeepSeek-ключа (в «Настройках» — это API-запрос, сервер сам проверяет его токен и роль, а не браузер).
- Ключ DeepSeek хранится в базе на сервере и никогда не возвращается обратно в браузер — только пометка «задан / не задан».
- Отправленное фото сервер сам отправляет в DeepSeek (если ключ задан), используя свой ключ, а не ключ пользователя.
- Подтвердить/отклонить/удалить обращение может только тот, чей токен на сервере проверился как `role='admin'` — это решает сервер, не JS в браузере.

## Локальный запуск

```bash
cd backend
npm install
cp .env.example .env     # заполнить: DATABASE_URL, JWT_SECRET, ADMIN_EMAIL, ADMIN_PASSWORD
npm run create-admin      # создаёт вашу единственную админ-учётку
npm start
```
Откройте `http://localhost:8080` — это уже и сайт, и API вместе.

Для `DATABASE_URL` локально проще всего поставить Postgres через Docker:
```bash
docker run --name regionwatch-db -e POSTGRES_PASSWORD=pass -p 5432:5432 -d postgres
# DATABASE_URL=postgres://postgres:pass@localhost:5432/postgres
```

## Деплой на Render (со своим доменом)

1. Залейте всю папку `region-watch-full` (обе подпапки) в репозиторий на GitHub.
2. На render.com → **New → Web Service** → подключите репозиторий.
3. Настройки сервиса:
   - Root directory: `backend`
   - Build command: `npm install`
   - Start command: `npm start`
4. В разделе Environment добавьте переменные из `.env.example` (`DATABASE_URL`, `JWT_SECRET`, `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `ALLOWED_ORIGINS` — можно указать `*` временно, потом сузить до вашего домена).
5. **Postgres**: Render → New → PostgreSQL (бесплатный план подходит для старта) → скопируйте его `Internal Database URL` в `DATABASE_URL` вашего веб-сервиса.
6. После первого деплоя один раз выполните создание админа. Проще всего — временно добавить `npm run create-admin` в build command, задеплоить, затем вернуть обратно на `npm install`. (Либо через Render Shell, если он у вас включён.)
7. **Свой домен**: в настройках сервиса Render → Custom Domain → впишите ваш домен → в панели регистратора домена добавьте CNAME/A-запись, которую покажет Render. HTTPS-сертификат Render выпускает сам, бесплатно.

## DDoS-защита

1. Приложенный уровень уже есть в коде: `express-rate-limit` на весь API и отдельно, жёстче — на вход/регистрацию.
2. Поставьте домен за **Cloudflare** (бесплатный план): зарегистрируйте домен там как DNS-провайдера, направьте на Render — это добавляет фильтрацию трафика ещё до того, как он доходит до вашего сервера. Это самая весомая часть защиты — приложенные лимиты выше защищают только от небольших/точечных злоупотреблений, а не от настоящей волны трафика.

## Что можно улучшить дальше (не сделано сейчас, чтобы не раздувать объём)

- Фото сейчас хранится как base64 прямо в базе — при росте объёма лучше перенести на S3-совместимое хранилище (поле `image_data` легко заменить на `image_url`).
- Восстановление пароля по email не реализовано — если понадобится, это отдельная функция (нужен email-провайдер, например Resend или SendGrid).
